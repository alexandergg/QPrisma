# Project Governance

## Overview

This document outlines the governance model for the QPrisma project. It defines the roles and responsibilities of community members and the decision-making process.

## Roles

### Contributors
Anyone who contributes to the project (code, documentation, issues, discussions) is a Contributor.
- **Responsibilities:** Follow the Code of Conduct and Contributing Guidelines.
- **Rights:** Submit PRs, report issues, participate in discussions.

### Maintainers
Contributors who have shown dedication and deep understanding of the project.
- **Responsibilities:**
  - Review and merge Pull Requests.
  - Triage Issues.
  - Guide the technical direction.
  - Enforce the Code of Conduct.
- **Rights:** Commit access to the repository, management of issues/labels.

### Admin / Project Lead
The project founder/owner.
- **Responsibilities:** Final say in architectural decisions if consensus cannot be reached. Management of sensitive credentials and infrastructure.

## Decision Making

### Consensus
We strive for consensus implementation. Major changes (architecture, breaking APIs) should be discussed in a GitHub Issue or Discussion before implementation.

### Lazy Consensus
If a proposal receives no objections within 72 hours (excluding weekends), it is assumed to be accepted.

### Conflict Resolution
If consensus cannot be reached, the Project Lead has the casting vote.

## Promotion
Contributors can become Maintainers by invitation from existing Maintainers, based on consistent and high-quality contributions.

## Removing Maintainers
Maintainers who are inactive for >6 months or violate the Code of Conduct may have their privileges revoked.
