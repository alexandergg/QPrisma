# Run Evaluation Skill

Run QPrisma evaluation benchmarks against the video understanding pipeline.

## Prerequisites

Before running any evaluation, verify infrastructure is ready:

```bash
cd backend && .venv/Scripts/python.exe .claude/skills/run-eval/scripts/check_infra.py
```

If the check fails, guide the user to start the required services:
- API: `cd backend && python api/main.py`
- Neo4j: `docker-compose up -d neo4j`
- Redis: `docker-compose up -d redis`

## Evaluation Modes

Determine which mode the user wants based on their request. If unclear, default to **quick custom benchmark**.

### Mode 1: Quick Custom Benchmark (Default)

Runs the QPrisma-authored benchmark against the already-indexed Microsoft Ignite Keynote video.

**10-question quick run:**
```bash
cd backend && .venv/Scripts/python.exe -m evaluation.scripts.run_first_eval
```

**30-question expanded run:**
```bash
cd backend && .venv/Scripts/python.exe -m evaluation.scripts.run_first_eval --expanded
```

**Using the evaluation framework with custom_eval config:**
```bash
cd backend && .venv/Scripts/python.exe -m evaluation.run_evaluation --config evaluation/configs/custom_eval.json
```

Results are saved to `backend/evaluation/results/first_eval/` or the configured output directory.

### Mode 2: Video-MME Full Evaluation

Requires Video-MME benchmark data to be downloaded and videos indexed first. See `references/BENCHMARKS.md` for setup instructions.

```bash
cd backend && .venv/Scripts/python.exe -m evaluation.run_evaluation --config evaluation/configs/video_mme_full.json
```

### Mode 3: MLVU Full Evaluation

Requires MLVU benchmark data and indexed videos. See `references/BENCHMARKS.md` for setup.

```bash
cd backend && .venv/Scripts/python.exe -m evaluation.run_evaluation --config evaluation/configs/mlvu_full.json
```

### Mode 4: Ablation Study

Runs 8 QPrisma variants + naive-rag baseline to measure each component's contribution.

```bash
cd backend && .venv/Scripts/python.exe -m evaluation.run_evaluation --config evaluation/configs/ablation_study.json
```

Variants tested: full, noagent, flat, vectoronly, norerank, visualonly, audioonly, fixedtokens.

### Mode 5: Custom Config

User provides a config JSON file path:

```bash
cd backend && .venv/Scripts/python.exe -m evaluation.run_evaluation --config <path-to-config.json>
```

Or via CLI arguments:

```bash
cd backend && .venv/Scripts/python.exe -m evaluation.run_evaluation \
    --benchmark <name> \
    --data-path <path> \
    --video-dir <path> \
    --methods qprisma-full naive-rag \
    --output-dir evaluation/results/<name>
```

## Result Presentation

After the evaluation completes:

1. Read the report JSON from the output directory
2. Present results in a formatted table showing:
   - **Accuracy** per method (overall and by category)
   - **Efficiency** (avg latency, tool calls)
   - **Per-question breakdown** showing correct/incorrect for each method

Example format:
```
Method                   Accuracy    Avg Latency    Avg Tool Calls
--------------------------------------------------------------
QPrisma (Full Agent)       80.0%       12,345ms            3.2
Direct Search (No Agent)   60.0%        2,100ms            1.0

Category              QPrisma    Baseline
-----------------------------------------
topic_understanding     100.0%      50.0%
visual_perception       75.0%       75.0%
```

3. Read `REPORT.md` if generated by the full pipeline
4. Highlight key findings (where QPrisma excels vs baseline, failure patterns)

## Error Handling

| Error | Fix |
|-------|-----|
| `ConnectionRefusedError` | Start the API server: `cd backend && python api/main.py` |
| `401 Unauthorized` | Check credentials in `run_first_eval.py` or `.env` |
| `Video not found` | Verify the video is indexed: search for it via API |
| `Timeout` | Increase timeout in adapter, or reduce `max_concurrent` |
| `ModuleNotFoundError` | Activate venv: `.venv/Scripts/activate` |
| `Benchmark file not found` | Check `data/benchmarks/` directory exists with benchmark.json |
